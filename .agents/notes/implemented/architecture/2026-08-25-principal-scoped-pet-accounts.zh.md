# Agent Note: 按身份隔离的宠物账号

Status: implemented

## Problem

宠物服务把唯一一只宿主全局宠物存入 `$DSH_HOME/pet.json`，浏览器设置则使用宿主全局的 `pet` 设置命名空间，因此每个浏览器访问的都是同一份宠物选择、名字、布局、开关、亲密度与小鱼干。账号网关可以隐藏全局设置命名空间，但这样会让账号没有宠物；将其暴露又会允许一个账号修改所有账号的宠物。账号选择不能信任用户名、请求体、Cookie 或未签名的浏览器请求头。

## Decision

`@linxin666/dsh-pet` 自己负责账号隔离，并在每次宠物 API 请求时解析账号：

- 没有已认证身份的请求属于直连桌面账号，沿用既有 `$DSH_HOME/pet.json` 文件、宿主设置组合和宿主全局会话活动。
- 携带可选宿主 `requestPrincipal` 服务验证过的身份时，请求按 `(principal.source, principal.id)` 二元组选择账号。该二元组经 SHA-256 哈希映射到不透明的 `$DSH_HOME/pet-accounts/<digest>/pet.json` 目录；用户名与浏览器提供的路径不参与映射。
- 验证器缺失或拒绝身份时，身份头或签名头均按失败关闭处理。宠物服务不自行解析网关凭据，也不接受 JSON 请求体中的身份字段。
- 浏览器设置卡片从 `/api/pet/settings` 读取并向 `/api/pet/settings/mutate` 写入，因此宠物选择、显示配置、可见性、账号启用开关与装饰开关和互动、命名、玩法状态使用同一份按身份隔离的文件。带版本号的写入可防止并发标签页静默覆盖更新值。
- 插件加载期间宠物 API 路由始终保持注册。关闭一个账号只卸载该账号浏览器里的宠物，不能让其他账号无法访问路由。
- 按身份隔离的宠物不消费宿主全局会话活动或气泡。当前会话事件流没有通过验证的身份归属，返回空闲视图可以避免跨账号活动泄露；直接互动、玩法状态、亲密度、小鱼干、名字、选择、布局与开关仍按账号独立。

宠物持久化文档记录两个账号开关，以及账号设置 API 显式覆盖的字段。既有 `$DSH_HOME/pet.json` 缺少这些字段时按默认值读取。

## Alternatives considered

- 把宠物状态存入 `dsh-passwords`：拒绝，因为宠物插件拥有宠物数据与 API。把存储移入某个网关会让宠物与特定账号提供方耦合，也无法让其他通过验证的身份提供方获得同样行为。
- 使用用户名、网关 Cookie、查询参数或浏览器本地存储作为账号键：拒绝，因为用户名会变化，Cookie 是网关凭据而非持久身份，浏览器可控值也能在没有宿主验证时选择其他账号。
- 保留一只全局宠物并向每个账号暴露宿主 `pet` 设置命名空间：拒绝，因为宠物选择、位置、启用状态、命名、亲密度和小鱼干仍是共享可变数据。
- 只隔离持久化偏好，同时把宿主全局会话动画转发给每个账号：拒绝，因为气泡与活动阶段可能泄露其他账号正在工作。按账号提供活动需要权威生产者在会话事件中给出身份。
- 每个账号运行一个 DSH 宿主进程：拒绝，因为对这项状态隔离需求而言进程隔离成本过高，还会重复插件注册表、模型连接与生命周期管理。

## Consequences

- 直连宿主端口保留既有宠物与完整的会话响应行为。设置默认值与每个新建的已认证网关账号都默认关闭宠物；账号可单独开启，并在浏览器刷新与服务重启后保持该选择。账号改名时不变 ID 保持不变，因此宠物也保留。
- 删除或撤销外部账号只会阻止访问，不会删除其不透明宠物目录。存储保留遵循其他用户数据的保守规则，避免与账号提供方形成破坏性耦合。
- 网关部署必须安装兼容的宿主 `requestPrincipal` 验证器才能隔离账号。存在签名身份头但缺少该验证器时返回 403，不会回退到桌面账号。
- 在宿主会话流携带通过验证的身份归属前，网关账号宠物保持空闲。这是明确的隔离保证，不是尽力而为的活动过滤。
- 覆盖范围包含重载后的持久化、玩法状态在内的两个账号互不影响、伪造与篡改身份拒绝、可信身份 HTTP 路由、带版本号的设置写入和直连账号路径。
