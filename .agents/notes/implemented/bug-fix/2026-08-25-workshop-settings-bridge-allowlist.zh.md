# Agent Note: 创意工坊设置桥白名单

Status: implemented

## Problem

创意工坊为启用开关注册 `dsh-web-ui-market` 设置命名空间，但 rc.6 兼容设置桥的内置 dsh-web 全家桶白名单和包名别名都没有包含该命名空间。宿主官方设置 API 拒绝第三方命名空间时，设置桥也会省略创意工坊，因此即使创意工坊与设置桥插件都已加载，其一级设置分区仍显示「该设置段未暴露」。

## Decision

设置桥把 `dsh-web-ui-market` 视为已注册的 dsh-web 全家桶命名空间。内置回退列表包含它，显式 `web_settings_namespaces` 配置也把 `dsh-web-ui-market`、`dsh-client-ui-market`、`dsh-market` 与 `ui-market` 解析到同一命名空间。

既有白名单规则继续作为权威：只有创意工坊已在宿主设置接缝注册命名空间时，设置桥才会开放它。显式配置且非空的 `web_settings_namespaces` 列表仍只开放用户选择的条目；使用这类列表的部署必须加入一个创意工坊别名才能显示其开关。

## Alternatives considered

- 增加创意工坊专属设置 HTTP API：拒绝，因为兼容设置桥已经负责第三方设置传输、版本冲突保护、schema 校验、持久化和认证代理访问。为一个布尔字段再建传输会重复这些保证。
- 命名空间不可用时让创意工坊卡片假定 `enabled: true`：拒绝，因为开关看似可用却没有持久且权威的写入路径，用户配置也无法可靠关闭卡片。
- 通过设置桥开放所有已注册宿主设置命名空间：拒绝，因为全家桶白名单是安全边界。仅凭注册不能让无关或特权命名空间获得远程配置访问。

## Consequences

- 未配置 `web_settings_namespaces` 时，创意工坊卡片通过与其他 dsh-web 全家桶设置相同的回退桥加载，不再显示命名空间缺失提示。
- 显式白名单继续保持最小权限；需要配置创意工坊卡片时必须加入相应条目。
- 无需修改创意工坊客户端、设置 schema、持久化格式或安装网关。
- 测试覆盖回退列表、裸命名空间、包名别名、已注册集合交集与桥接 describe 响应。
