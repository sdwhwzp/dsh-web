# Agent Note: 工作区测试串行门禁

Status: implemented

## Problem

根级 `pnpm test` 会并发启动多个工作区测试脚本，同时每个 Vitest 包也会并行执行自身文件。大型浏览器测试套件因此可能争用 CPU 与内存，使原本确定性的 5 秒 UI 测试或 30 秒 HTTP 压力测试超时。同一测试在所属包拥有正常资源时可以通过，因此提高单项超时只会掩盖工作区级资源过量使用，而不能修复它。

## Decision

根级测试门禁以 `--workspace-concurrency=1` 运行各工作区测试脚本。Vitest 仍可在每个包内部并行测试文件，直接过滤到单包的测试命令也保持原有行为。相比跨包并行带来的较短但不可靠的耗时，门禁优先提供确定性的完整结果。

## Alternatives considered

提高单项测试超时被否决，因为资源争用时不同套件会轮流成为最慢项，而且更长的限制会延迟发现真实挂起。

工作区并发二被否决，因为它虽然消除了短 UI 测试超时，但仍让 Skin Center 的场景探测缓存压力测试超过其明确的 30 秒预算。

关闭或降低包内 Vitest 并行被否决，因为争用来自独立启动的工作区进程之间，而每个包仍能从自身有界并行中获益。

## Consequences

`pnpm test` 耗时增加，但在开发机器与 CI runner 上拥有稳定的资源上限。聚焦到单包的测试仍然快速，现有超时预算继续保留诊断价值，运行时与发布包行为均不改变。
